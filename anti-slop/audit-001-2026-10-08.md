# Auditoría visual y de usabilidad 001

Fecha: 2026-10-08
Modo: AFTER
Alcance: `apps/web/src`, con foco en autenticación y shell autenticado.

## Hallazgos

### 1. [MEDIUM] La navegación móvil depende de scroll horizontal

**Evidencia:** `apps/web/src/shared/ui/app-shell.tsx:96-107` usa `overflow-x-auto` para mantener todos los destinos en una sola fila.

**Regla:** R-03, Layoutmobile: la navegación móvil debe reordenarse como menú o navegación primaria compacta, no trasladar la fila de escritorio a scroll lateral.

**Impacto:** los destinos secundarios quedan ocultos y el usuario debe descubrir que existe desplazamiento horizontal.

**Corrección propuesta:** mantener visibles los destinos principales y agrupar Equipo y Configuración en un menú accesible con teclado, o convertir la navegación en una lista replegable.

### 2. [MEDIUM] Estados de error incompletos en bandeja

**Evidencia:** `apps/web/src/features/inbox/InboxPage.tsx:91-95` contempla carga y vacío, pero no renderiza un estado de error para `conversations.error`.

**Regla:** R-27 y C-4: toda vista con datos necesita estados de carga, vacío y error perceptibles, con una acción siguiente.

**Impacto:** una caída de API puede verse como una bandeja vacía o quedar sin explicación ni recuperación.

**Corrección propuesta:** agregar mensaje específico, botón de reintento y anuncio accesible para el error de conversaciones y mensajes.

### 3. [LOW] El shell no usa el gesto visual de marca definido

**Evidencia:** `apps/web/src/shared/ui/app-shell.tsx:37-40` renderiza `⌂` como logo, mientras `apps/web/src/styles.css:27-55` define `.bee-mark` y `AuthLayout` sí lo usa.

**Regla:** R-20 y R-31: la identidad debe ser consistente y cada decisión visual debe tener un propósito.

**Impacto:** login y aplicación parecen productos distintos y el icono de casa no comunica BeeCRM.

**Corrección propuesta:** reutilizar el componente/marca de abeja en el shell y conservar el texto BeeCRM como nombre accesible.

### 4. [LOW] La iconografía del shell mezcla símbolos tipográficos sin semántica consistente

**Evidencia:** `apps/web/src/shared/ui/app-shell.tsx:24-33, 136` usa caracteres `⌂`, `▣`, `♙`, `♧`, `⚙` como iconos.

**Regla:** R-04: un icono debe ser relevante y conservar una lectura clara, especialmente con lector de pantalla.

**Impacto:** los símbolos no tienen significado uniforme y pueden anunciarse como contenido extraño si no quedan completamente decorativos.

**Corrección propuesta:** usar iconos SVG propios y relevantes con `aria-hidden`, dejando el texto como fuente principal de significado.

### 5. [LOW] La autenticación mantiene controles visuales sin comportamiento

**Evidencia:** `apps/web/src/shared/ui/form.tsx:52-55` muestra `ES` y `☾` como elementos estáticos.

**Regla:** R-26: todo control debe tener comportamiento real; si no existe cambio de idioma o tema, no debe presentarse como control.

**Impacto:** la luna comunica una posibilidad de tema que el usuario no puede activar y genera una expectativa falsa.

**Corrección propuesta:** eliminar el indicador hasta implementar el comportamiento, o convertirlo en un botón accesible con estado y persistencia reales.

## Decisiones de diseño auditadas

- Dirección válida encontrada en `DESIGN.md`: ENERGY 2 / RHYTHM 2 / MOTION 1.
- La paleta miel sobre neutros está alineada con la dirección existente.
- No se detectó un gradiente genérico ni una acumulación de glassmorphism; el único `backdrop-blur` relevante está en el header.
- Los radios, sombras y tamaños de controles están relativamente alineados con la dirección, pero requieren revisión al corregir la navegación móvil.

## Seguridad: observaciones separadas

1. **Resuelto:** el arranque fallaba por variables opcionales vacías de IA inyectadas por Docker. El parser ahora normaliza `''` a ausente sin relajar las exigencias cuando `LLM_API=openai` o `EMBEDDINGS_API=openai`.
2. **Alta prioridad para entornos compartidos:** `docker-compose.yml:128-131` expone Grafana con acceso anónimo y rol `Admin`. Aunque está bajo el perfil local, ese perfil no debe publicarse en una red compartida.
3. **Alta prioridad para entornos compartidos:** Postgres, Valkey, Mailpit, API y observabilidad publican puertos en todas las interfaces (`docker-compose.yml:22,33,42,70,82,111,119,127`). En desarrollo local conviene bindearlos a `127.0.0.1`; en producción no se debe usar este compose como perímetro.
4. **Control existente:** Helmet, verificación de origen, rate limiting, bloqueo por intentos y guards de sesión/permisos están presentes. No afirmo que eso sustituya una prueba de despliegue, secretos y proxy TLS.
